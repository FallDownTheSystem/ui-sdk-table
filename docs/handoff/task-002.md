## Goal
The user wants these results:

1. Rewrite the table (`src/components/CustomTable/`, `src/composables/table/`) as a truly headless table: better composables, no forced feature set, no hardcoded styles.
2. Fix the performance and reactivity problems of the current table. Diagnose each before the fix; remove the enabling structure, not only the symptom.
3. Add: column resize, column pinning, column order (drag to reorder), cell editing with validation, cell range selection, arrow-key grid navigation with correct grid ARIA, row pinning, server-side mode for sort, filter and pagination.
4. Rebuild the styled table on top of the new headless layer.
5. Separate the table into its own project, outside dashboard-template.

Keep every current feature: sort and multi-sort, global filter, column filters with filter types and date ranges, facets, pagination, row selection, row expansion, tree rows through a children key, multi-level grouping, aggregation and footer totals, nested column headers, column visibility, sticky header and footer, virtual rows (fixed and dynamic), CSV and Excel export, formatters, translated labels, slot-based cells.

Direction already accepted by the user (earlier session, other repository): keep the own data model, do not adopt TanStack Table v9 or Vuetify0, use UI SDK behaviors for the interaction layer.

- **P3** "They [the composables] should be based on the design principles of ui-sdk, which includes agent first design, do look into ui-sdk docs thoroughly for ideas of abstraction and to make it consistent." *You, 2026-11-20.* Agent reading of the UI SDK docs (beta.13: `core.md` Define a Primitive, Handle Changes, Customize a Behavior, All Behaviors, Grids, Editing in Place; `agents.md` The Agent Key, Permissions, Custom Primitives):
  - One `definePrimitive` definition per component: `options` schema with kinds, `state`, `sync`, `controlled`, `api`, `slots`, `agent`. Framework-free; adapters render with `createParts` / `usePrimitive` / `usePart`.
  - Behaviors are `create<Thing>(context, options)`; rules are function options; results come back through `set` / `onMove` / return values; behaviors do not know each other and meet only in `api`.
  - State contract: `<key>`, `default<Key>`, `on<Key>Change(value, details)`; every user-visible change goes through `createChange` with a `reason` (shared `ReasonVocabulary` first), `source` (includes `agent`), `cancel()`. Drags use `createCommit` (`on<Key>Commit`). Actions without state use `dispatch`.
  - Slots: role on the slot (TypeScript then requires `focus` / `press` / `keys`), pure `attrs`, `data-slot` from the primitive name, state as ARIA and `data-*`, values as CSS variables, `selects` / `live` / `direct` (`byCell`, `byCellRange`) for updates that reach only the affected parts.
  - Agent-first: `agent: { actions, closed, items, reveals, shown, secret }`; accessible name on the root; snapshot shows `controlled` keys; action methods validate their arguments and throw a message that lists valid values; every control an agent uses must be a UI SDK part; `data-agent-confirm` / `-secret` / `-hidden` marks.
  - Outside access through `createController`, not template refs.
  - Pure helpers work without a primitive (`visibleTreeRows`, `createTreeCollection`, `fuzzyScore`, `cellsToText`).
