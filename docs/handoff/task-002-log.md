One independent review with browser runs: 15 findings, all fixed with a test each except one that became a written rule.
**Decisions:** The frame is the nearest parent whose content is higher than itself, chosen again at each read · a wrapper with `overflow-x: auto` has the same computed `overflow-y` as a real frame and switched the window off · rejected the computed style alone. Every scroll that the table makes is `behavior: 'instant'` · with `scroll-behavior: smooth` a jump never arrived. With `hasDetail`, rows are measured also when `rowHeight` is set · a detail row has its own height, and the rows in view jumped by 70 pixels · rejected an error for the two options together. Sticky rows count with their heights, not with their place on the screen · a header that is not at its edge yet gave a wrong place for `start` and `center`. A press on a row never scrolls; only a key or a row that is not rendered does · the row is under the pointer. The active cell follows its row when rows above it are pinned or open · the cell that has focus is the same element. Totals count the rows that pass the filter · a pinned row that the filter refuses is shown and not counted; the rule is in the text of `rowPinning` · rejected a second total.
**Learned:** (1) Inside a ResizeObserver callback, a change of state that adds rows gives "ResizeObserver loop" errors. Write only the scroll position there and work the rows out in the next frame. (2) A renderer can call `bind` before the element is in the page; a search for parents must wait. (3) Slot names must be kebab-case: the markup of `mount` is HTML, and a capital letter in a tag never matches a part. (4) `overflow-anchor` must be `none` on the frame, or the browser corrects a measured height a second time; two tables in one frame need a count. (5) `el.focus()` from a script scrolls a cell that a sticky row cuts, also on a press; focus with `preventScroll` first, and the grid does not move focus again. (6) Rows with heights of half a pixel make a jump correct itself by one pixel; a test for "one direction" needs that tolerance. (7) jsdom has no layout: the frame choice, smooth scrolling and detail heights are tested only in Playwright.
